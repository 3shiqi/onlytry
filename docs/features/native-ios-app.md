# Feature: Native iOS App

## Purpose

Provide an installable native iPhone app for `onlytry` while preserving the web/PWA product path.

The native app is intentionally small:

- `Session`: generate today's training from the local exercise database and execute it immediately
- `Library`: browse the exercise library and add professionally tagged exercises
- `Calendar`: review completed native training sessions

## Runtime Architecture

The native app uses SwiftUI and SwiftData.

`OnlytryApp.swift` creates one `ModelContainer` for:

- `Exercise`
- `SessionLog`

`RootTabView` owns the three-tab shell and runs `ExerciseSeedData.seedIfNeeded(context:)` on launch. This means any tab can be opened first and still receive the starter action library.

## Data Model

The master model is `Exercise` in `ExerciseModel.swift`.

It follows the V4 medical-grade action-library structure:

- `AnatomyData`
- `BiomechanicsData`
- `ProgrammingData`
- `EnergySystem`
- `LogisticsData`
- `ClinicalData`
- `CoachingData`
- `MediaData`

The model keeps professional tags grouped by domain instead of flattening everything into one record. For example, coaching cues are accessed from `exercise.coaching.cues`, and clinical guardrails are accessed from `exercise.clinical.contraindications`.

`SessionLog` stores completed native sessions for the Calendar tab.

## Seed Data

`ExerciseSeedData.swift` inserts starter exercises only when the local SwiftData exercise table is empty.

- Warm-up: 2

## Session Logic

`WorkoutPlanner.todayPlan(from:)` reads all local `Exercise` records and selects exercises in CSCS order:

1. `Warm-up`
2. `Power`
3. `Strength`
4. `Core`
5. `ESD`
6. `Hypertrophy`

Default quota:

- `Warm-up`: 2
- `Power`: 1
- `Strength`: 3
- `Core`: 1

Candidate selection is deterministic for now:

- filter by `exercise.programming.phaseCompatibility`
- skip already selected exercises
- sort by lower `cnsCost`
- use exercise name as tie-breaker

This keeps the first native version predictable. If future versions need freshness, add a cooldown/randomization layer here.

## Library Logic

`ExerciseLibraryView.swift` supports:

- list browsing
- search by name, tags, and pattern
- detail view for biomechanics, programming, coaching cues, and clinical guardrails
- add-exercise sheet with professional fields

When adding a new exercise, comma-separated fields become arrays.

Important add form mappings:

- `pattern` -> `BiomechanicsData.pattern`
- `phase` -> `ProgrammingData.phaseCompatibility`
- `trackingMetrics` -> `LogisticsData.trackingMetrics`
- `cueText` -> `CoachingData.cues`
- `contraindications` -> `ClinicalData.contraindications`

## Calendar Logic

`TrainingCalendarView.swift` reads `SessionLog` records from SwiftData.

The current calendar is intentionally simple:

- current-month grid
- today is highlighted
- logged days get a small green marker
- history list shows completed sessions below the grid

The web app has a richer algorithmic calendar. If native Calendar should match it later, port the web `calculateFluidCalendar` behavior into a Swift planner and add a `PlayLog` model.

## Project Configuration

Native iOS defaults:

- Display name: `Onlytry`
- Bundle ID: `com.sunshiqi.onlytry`
- Marketing version: `0.7.0`
- Minimum iOS: `17.0`
- CocoaPods: not required for the current native target

The iOS project was originally generated by Capacitor, but the current native target no longer uses the Capacitor storyboard bridge. The active build target references only:

- SwiftUI source files
- `Assets.xcassets`
- `LaunchScreen.storyboard`
- `Info.plist`

Legacy WebView files may still exist on disk for history, but they are no longer part of the native target resources or sources.

## Safe Change Points

Use these entry points for future changes:

- add fields to the medical model: `ExerciseModel.swift`
- add default exercises: `ExerciseSeedData.swift`
- change today's algorithm: `WorkoutPlanner.swift`
- change execution UI: `SessionView.swift`
- change action-library UI: `ExerciseLibraryView.swift`
- change month/history display: `TrainingCalendarView.swift`
